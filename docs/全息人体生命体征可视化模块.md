# 开发任务：全息人体生命体征可视化模块

## 一、项目背景

当前项目需要增加人员生命体征查看功能。

用户在现有人员列表、人员标记或三维场景中点击某个人员后，弹出一个具有科幻医疗科技感的三维人体可视化界面，用于展示当前人员的生命体征和健康监测数据。

请参考我提供的图片，重点还原以下视觉特征：

- 正面站立的完整人体，头部、躯干、双臂和双腿均清晰可见。
- 深海军蓝色背景，人体呈半透明的蓝色全息影像。
- 人体轮廓具有明亮的青蓝色荧光描边。
- 身体内部可以看到血管、骨骼或解剖结构的层次。
- 心脏区域以橙红色或红色高亮显示。
- 血管以红色和蓝色区分动脉与静脉的视觉表现。
- 底部具有蓝色发光的圆形扫描平台。
- 背景可以包含科技网格、扫描线、HUD 标记和微弱粒子。
- 整体呈现高质量的医疗科幻可视化效果，而不是普通的卡通人体、扁平 SVG 插画或传统后台管理弹窗。

## 二、技术要求

请首先分析当前项目的技术栈、组件组织方式、现有人员详情交互和三维渲染架构，再决定具体实现方案。

优先使用项目现有技术栈，不要擅自重构现有业务。

如果项目使用 Vue 3 + TypeScript + Three.js，请采用以下技术方案：

- Vue 3 Composition API 和 TypeScript。
- Three.js 负责人体模型、材质、灯光、扫描平台和动画。
- 使用 GLTFLoader 加载高质量 GLB/GLTF 三维人体模型。
- 使用透明材质、青蓝色发光效果、边缘光和后处理 Bloom 增强全息视觉。
- 使用 CSS 实现弹窗布局、数据卡片、HUD 标注和扫描线等界面元素。
- 使用 requestAnimationFrame 驱动必要的动画，确保渲染循环可控。
- 如项目已有 Three.js 封装、渲染器或后处理系统，优先复用。
- 不要为了实现该功能引入不必要的大型依赖。

## 三、人体模型要求

优先采用真实的三维人体解剖模型，而不是通过球体、圆柱体等基础几何体拼接成人体。

模型应满足：

1. 正面站立，身体比例自然，人体结构完整。
2. 可以看出人体轮廓以及内部血管或解剖结构。
3. 支持半透明、青蓝色发光和局部高亮效果。
4. 心脏区域可以单独识别和高亮。
5. 如果模型包含独立的器官、骨骼或血管 Mesh，建立可配置的部件索引。
6. 如果模型不包含真实内部解剖结构，不要通过修改普通人体材质就宣称实现了解剖可视化。
7. 如果暂时没有合适的模型资源，请实现清晰的模型加载接口、占位状态和可替换的演示模型，不要假装已经加载真实解剖模型。

人体模型、材质、器官部件和生命体征数据应尽可能解耦，方便后续替换高质量模型。

## 四、交互流程

### 1. 打开人体监测面板

用户点击某个人员后：

- 获取当前人员的 ID、姓名和相关业务数据。
- 打开人体生命体征详情面板。
- 将当前人员信息传入组件。
- 初始化或复用 Three.js 场景。
- 展示正面站立的全息人体。
- 显示该人员的生命体征数据。

### 2. 人体交互

- 默认正面展示完整人体。
- 可以通过鼠标拖动旋转人体。
- 支持滚轮缩放，但限制合理的缩放范围。
- 支持恢复默认视角。
- 可以点击心脏、头部、胸部等可识别区域。
- 点击人体区域后，高亮对应部位，并显示相关数据或提示。
- 如果人体模型暂时不支持真实器官拾取，请将交互能力设计为可扩展接口。

### 3. 关闭面板

- 支持点击关闭按钮或按 Escape 关闭。
- 关闭时停止不必要的动画与数据订阅。
- 正确处理 Three.js 资源的释放或场景复用。
- 避免重复打开导致多个渲染循环、事件监听器或 WebGL 上下文泄漏。

## 五、生命体征数据展示

在人体周围或右侧信息区域展示以下数据：

- 心率：bpm。
- 血氧饱和度：SpO₂，%。
- 体温：℃。
- 呼吸频率：次/分钟。
- 血压：收缩压/舒张压，mmHg。
- 数据更新时间。
- 数据来源与设备连接状态（如果项目具备这些数据）。

可根据数据与经过确认的参考范围，展示正常、关注或异常等状态。

视觉要求：

- 重要数据使用清晰的大号数字。
- 数据卡片采用深蓝半透明背景、青蓝色描边和微弱荧光效果。
- 心率可以使用轻量化动态波形。
- 心脏高亮与心率数据联动。
- 支持数据实时更新，不应因为数据刷新而重新创建整个 Three.js 场景。
- 无数据时显示“暂无数据”，不要自动填入看似真实的健康数据。

当前没有真实数据接口时，请提供明确标记的 Mock 数据适配器，方便后续接入后端或穿戴设备。

## 六、页面布局

采用深色医疗科技风格，建议分为三个区域：

1. 中央区域：全息人体模型，占据主要视觉空间。
2. 左侧区域：人员身份、设备状态、心率和血氧等重要指标。
3. 右侧区域：血压、体温、呼吸频率、历史趋势等信息。

在较小屏幕或弹窗尺寸不足时，允许切换为中央人体加底部指标卡片的布局。

背景保持简洁，避免过多的装饰影响数据可读性。

## 七、动画与性能

- 人体默认缓慢呼吸或进行轻微的悬浮动画。
- 扫描平台具有低频率、低强度的发光动画。
- 扫描线可以周期性经过人体。
- 心脏区域可以通过柔和的脉冲高亮体现心跳。
- 心率变化驱动的是有数据依据的可视化表现，不应仅凭动画推断真实心脏状态。
- 动画应可暂停，并尊重减少动态效果的系统偏好。
- 页面关闭或隐藏时暂停非必要渲染。
- 对高成本后处理、透明材质和粒子效果进行性能控制。
- 优先确保人体轮廓、解剖结构和数据可读性，不要为了特效牺牲帧率。

## 八、组件设计建议

请结合现有项目架构进行调整，可以参考以下拆分：

- `VitalSignsDialog.vue`：面板容器和打开关闭逻辑。
- `HumanBodyScene.vue`：Three.js 场景与人体渲染。
- `HumanBodyModel.ts`：人体模型加载、部件索引和模型状态。
- `HumanBodyEffects.ts`：全息材质、扫描线、心脏高亮等效果。
- `VitalSignsPanel.vue`：生命体征数据展示。
- `VitalSignsWaveform.vue`：心率波形可视化。
- `vitalSigns.types.ts`：人员及生命体征类型定义。
- `vitalSigns.adapter.ts`：Mock 数据与真实 API 的适配接口。

以上只是建议，优先遵循项目现有的组件和目录规范，不要为了满足命名而重复创建已有模块。

## 九、验收标准

1. 点击人员后，可以打开人体生命体征面板，并展示正确的人员信息。
2. 人体呈现蓝色半透明全息视觉效果，具有清晰轮廓、内部结构和发光平台。
3. 人体不是简单的平面图片；如使用三维模型，应支持实际的三维相机和交互。
4. 生命体征数据与当前人员正确关联。
5. 数据更新不会导致整个三维场景反复初始化。
6. 打开、关闭和重复打开面板不会造成明显的内存或渲染资源泄漏。
7. 无真实数据时明确展示演示状态或暂无数据。
8. 所有交互可以正常工作，不影响现有人员管理业务。
9. 在完成实现后，说明使用的模型资源、依赖、主要文件、运行方式、尚未实现的能力及后续接入真实数据的方法。

请先阅读项目代码，给出简短的实现计划和关键文件分析，然后分阶段实现：

第一阶段：完成面板布局、深色 HUD 视觉和人体模型展示。

第三阶段：接入人员信息与生命体征数据。

第四阶段：实现人体交互、数据更新、资源释放和性能优化。

请优先交付可以在当前项目中运行的实际代码，不要只输出设计方案或静态代码示例。
