# 全息人体生命体征可视化模块

> 状态：已落地（Mock 数据 + 点云全息 HUD）。本文档描述当前仓库中的实际实现，而非早期设计草案。  
> 姊妹方案（病毒三维监控面板，阶段 0–4 已落地）见 [`病毒健康监控全息面板方案说明.md`](./病毒健康监控全息面板方案说明.md)；该面板复用本文基建模式，但不改写本模块人体系实现。

## 一、模块定位

在三维工地场景中提供「人员健康监测」能力：选中工人或进入健康大屏后，打开深色医疗科技风面板，展示全息人体与生命体征数据。

核心视觉不是解剖器官可交互人体，而是：

- 从普通人体 GLB（`/model/man.glb`）面积加权采样得到的青蓝色点云剪影
- 半透明菲涅尔「皮肤壳」
- UnrealBloom 轻度溢光
- 脚下扫描底座 + 沿身高上下移动的扫描环
- CSS HUD（蜂巢指标、引线标注、心电图 / 趋势、时间轴）

数据层当前为显式 Mock 适配器（`source: 'mock'`），UI 会标明演示状态；阈值仅供演示分级，不作医疗诊断依据。

## 二、技术栈与架构原则

| 项 | 实现 |
|----|------|
| 框架 | Vue 3 Composition API + TypeScript（`<script setup lang="ts">`） |
| 状态 | Pinia `useSiteStore`（无独立 vitals store） |
| 三维 | Three.js；面板内独立 WebGL 视口，不复用主场景渲染循环 |
| 人体表现 | GLTFLoader 加载 GLB → 采样点云 + 菲尼尔壳（加载后原 mesh 树 dispose） |
| 后处理 | `EffectComposer` + `UnrealBloomPass` |
| UI | Vue 组件 + SCSS HUD；波形用 Canvas |
| 动效偏好 | `usePrefersReducedMotion`；尊重系统「减少动态效果」 |

原则：不改动既有施工场景主业务；健康能力以叠加面板 + store 扩展接入。

## 三、入口与交互流程

无独立路由；`App.vue` 挂载 `ConstructionScene`，由本地 ref + `siteStore` 编排。

### 3.1 打开路径

| 入口 | 触发 | 行为 |
|------|------|------|
| 场景点选工人 | `InteractionManager` → `store.selectObject`；`objectType === Worker` | `loadWorkerVitals(businessKey)`；显示 `WorkerHealthPanel` |
| 左侧信息面板 | 「打开全息人体演示」→ `toggleHologramPreview` | 未选工人时切 `demoHologramVisible`，`loadDemoVitals()`；已选工人时等价于关闭面板 |
| 健康监测大屏 | 「进入健康监测大屏」→ `toggleHealthOps` | `healthOpsMode = true`，显示 `HealthOpsHud`；工人脚下光圈可见；约每 10s `refreshOverview` |
| 大屏名册 | 点击人员卡片 | `selectByBusinessKey` 聚焦场景工人并打开面板 |
| 大屏「全息演示」 | `handleOpenDemo` | 清除选中 + `loadDemoVitals()` |

可见性（`ConstructionScene.vue`）：

- `healthPanelVisible = isWorkerSelected || demoHologramVisible`
- `healthDemoMode = demoHologramVisible && !isWorkerSelected`
- 选中真实工人时强制关闭演示 flag

### 3.2 关闭与资源

- 面板「关闭」→ `closeHealthPanel`：关演示；若已选工人则 `clearSelection()`
- 卸载时 `HologramPointCloudPreview.dispose()`（geometry / material / composer / renderer / 事件 / RAF）
- 页签 `visibilitychange` → `setPaused`，隐藏时暂停非必要渲染
- **尚未实现 Escape 关闭**

### 3.3 换人与数据刷新

- `workerId` 变化 → `replayProjection()`：消散 → hold → 再聚合
- 面板用 `displayedVitals` + `hudHold`：resync hold 阶段再提交展示数据，避免 HUD 提前跳变
- 生命体征更新只走 `setVitals`，**不会**重建整个 Three.js 场景

## 四、页面布局

### 4.1 `WorkerHealthPanel`（全息面板）

深色医疗科技风，中央人体全铺，左右轨道叠加：

| 区域 | 内容 |
|------|------|
| 顶栏 | `BIOMETRIC SCAN / UPLINK`、本地时钟、关闭 |
| 中央 | WebGL 视口 + `BodyAnnotationOverlay`（头 / 胸 / 呼吸 / 腕引线） |
| 左轨（约 22% / 280px） | `WorkerIdentityRail`：姓名、ID、岗位、在岗、整体状态、风险摘要、穿戴设备、数据来源 / 演示标记 |
| 右轨（约 24% / 300px） | `VitalSignsHoneycomb` 七格指标；下方图表（选 `hr` 显示 ECG，否则近 15 分钟趋势） |
| 底栏 | `WorkerHealthTimeline` +「复位视角」「暂停 / 恢复扫描」 |
| 装饰 | 四角框、CSS scanline |

大屏模式下面板避让顶栏与左侧名册：`top: 88px; left: 284px; right/bottom: 16px`。

### 4.2 `HealthOpsHud`（人员健康监测大屏）

- 顶栏：在岗 / 关注 / 危急 / 设备在线率等汇总
- 左侧：工人名册与筛选
- 右侧：告警列表与分布（高心率、低血氧、发热等）
- 主场景 `WorkerHealthHaloController`：工人脚下按 `VitalsLevel` 着色并脉冲（仅大屏模式显示）

## 五、三维人体实现

### 5.1 渲染管线（`HologramPointCloudPreview`）

1. `createGltfLoader` 加载 `HOLOGRAM_PERSON_MODEL_URL`（`/model/man.glb`）
2. `sampleMeshToPoints`：面积加权过采样 → 轮廓权重收束到约 64 000 点
3. 点云着色器：呼吸 / 心率脉冲、告警部位着色（心 / 肺 / 头 / 腕）
4. `createHologramSurface`：网格克隆为半透明菲涅尔壳（非内脏解剖）
5. `createHologramPedestal`：脚下网格盘、细环、对向慢转弧、呼吸脉冲
6. `createHologramScanRing`：沿身高扫描（周期约 7.4s，可 `pulseScan` burst）
7. 额外砂粒 / 丝带 / 飞沫粒子（相对表面点比例见常量）
8. Bloom：`strength 0.14 / radius 0.32 / threshold 0.62`

### 5.2 相机与交互

| 能力 | 行为 |
|------|------|
| 旋转 | 指针拖转 → `userYaw`；拖转期间停自动微幅 yaw |
| 缩放 | 滚轮 → `cameraDistance`，夹在 `[2.05, 4.2]` |
| 复位 | `resetView()`：yaw = 0、距离回默认 |
| 暂停扫描 | `setPaused`；同时可暂停 ECG 动画 |
| 部位选择 | **非 3D 网格拾取**；2D 锚点标签：`head→temp`、`chest→hr`、`breath→rr`、`arm→spo2`（腕部可用点云 `estimateLeftWrist` 校正） |

### 5.3 与早期视觉目标的差异（明确）

| 早期设想 | 当前实现 |
|----------|----------|
| 半透明解剖人体、红蓝血管、橙红心脏 mesh | 点云剪影 + 菲涅尔壳；告警用着色器区域高亮 |
| 器官 Mesh 部件索引与 3D 拾取 | 未做；交互扩展点为 `BodyAnnotationOverlay` + `VitalMetricKey` |
| 建议命名 `VitalSignsDialog` / `HumanBodyModel` 等 | 采用 `WorkerHealthPanel` + `HologramPointCloudPreview` 等现有命名 |

模型资源：常量指向 `public` 路径 `/model/man.glb`；若本地缺失，视口会进入 `error` 状态并显示加载失败文案。

## 六、生命体征数据

### 6.1 展示指标

蜂巢七格（`VitalMetricKey`）：

| Key | 含义 | 单位 / 说明 |
|-----|------|-------------|
| `hr` | 心率 | bpm；联动 ECG 与点云脉冲 |
| `spo2` | 血氧饱和度 | % |
| `temp` | 体温 | ℃ |
| `rr` | 呼吸频率 | 次 / 分钟 |
| `bp` | 血压 | 收缩压 / 舒张压，mmHg |
| `fatigue` | 疲劳指数 | 演示扩展指标 |
| `gait` | 步态 | 部分工人 `available: false` 时显示不可用 |

另有：`updatedAt`、`source`、穿戴设备在线与电量、风险摘要、时间轴事件、近 15 分钟历史曲线。

状态分级：`normal | warning | critical`（文案：正常 / 关注 / 危急），阈值见 `constants/vitals.ts` 的 `VITALS_THRESHOLDS`。

无数据时蜂巢显示「暂无数据」，不伪造看似真实的业务读数（Mock 适配器本身会返回带 `source: 'mock'` 的演示包）。

### 6.2 数据层

| 层 | 位置 | 说明 |
|----|------|------|
| 类型 | `src/types/vitals.ts` | `WorkerHealthDetail`、`SiteHealthOverview`、`VitalAlert` 等 |
| Mock API | `src/api/vitalSigns.ts` → `vitalSignsApi` | `fetchByBusinessKey` / `fetchDemoProfile` / `fetchOverview` |
| 种子 | `SEEDS`：`worker:01`–`07`（含危急 `worker:07`） | `jitter` + 短 `delay` 模拟网络 |
| Store | `siteStore`：`selectedVitals`、`healthOverview`、`vitalsLoading`、`vitalsError` 等 | `loadWorkerVitals` / `loadDemoVitals` / `loadHealthOverview` / `workerLevelMap` |
| 格式化 | `src/utils/vitalsFormat.ts` | `buildHoneycombMetricViews`、`historyForMetric`、时钟与级别文案 |

演示档案：`fetchDemoProfile` 基于 `worker:01`，展示名可标为全息演示对象。

### 6.3 接入真实设备 / 后端（约定）

保持 `vitalSignsApi` 方法签名不变，将内部实现替换为真实请求即可；响应需继续满足 `WorkerHealthDetail` / `SiteHealthOverview`，并将 `source` 设为 `'device'`。UI 已按 `source` 区分 Mock 徽章。阈值与分级逻辑集中在 `constants/vitals.ts`，可按业务校准。

## 七、动画与性能

已实现：

1. 开场粒子散开汇聚（`HOLOGRAM_ASSEMBLE_*`）
2. 换人消散再聚合（`HOLOGRAM_RESYNC_*`）
3. 砂粒 / 丝带漂移
4. 心率驱动 `uPulse` 与胸区位移；告警部位着色
5. 未拖转时微幅身体 yaw（`HOLOGRAM_YAW_AMPLITUDE`）
6. 底座环旋转与呼吸透明度
7. 扫描环上下扫 + burst
8. Bloom、菲涅尔壳随 assemble 显现
9. HUD：scanline、蜂巢呼吸、标注 pulse、ECG 扫线、大屏名册与脚下 halo

`prefers-reduced-motion`：关闭扫描 / 脉冲 / 相关 CSS 动画；`setReducedMotion(true)` 时跳过 resync 长动画，直接满进度。

面板关闭或页签隐藏时暂停预览循环，避免重复打开造成多路 RAF / 多 WebGL 上下文。

## 九、运行与验收对照

### 运行

1. 确保可访问 `/model/man.glb`（与 `HOLOGRAM_PERSON_MODEL_URL` 一致）
2. 启动前端后：点场景工人，或左侧「打开全息人体演示」，或「进入健康监测大屏」

### 已满足

1. 点人员可打开面板并关联正确人员信息（Mock）
2. 青蓝色半透明全息剪影、Bloom、底座与扫描环
3. 真实 3D 相机：拖转、滚轮缩放、复位
4. 数据与当前人员 / 演示档案关联；刷新不重建场景
5. 打开 / 关闭 / 换人具备 dispose 与 pause；Mock 有明确标记
6. 不阻断既有人员与场景业务

### 已知缺口 / 后续方向

1. Escape 关闭面板
2. 真实解剖模型（血管 / 骨骼 / 可辨器官）与 3D 部件拾取
3. 将 `vitalSignsApi` 替换为设备 / 后端实时流
4. 时间轴目前只读，无 scrub / seek
5. 若需更接近早期概念图，可在保留点云壳的前提下叠加可配置器官高亮层，而不是回退到「改材质假装解剖」

## 十、设计取舍说明

早期任务书要求「高质量解剖 GLB + 器官拾取」。落地时优先保证：

- 可在现有工地场景中稳定运行的全息观感与性能
- 人员业务解耦、Mock 可替换
- 换人重扫描与 HUD 同步体验

因此采用 **GLB → 点云 + 菲涅尔壳** 方案，并额外交付了健康监测大屏与主场景脚下光圈。后续若引入解剖资产，应通过独立部件索引与加载接口扩展，避免污染当前点云预览主路径。
