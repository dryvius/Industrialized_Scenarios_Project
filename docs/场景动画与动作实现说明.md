# 场景动画与动作实现说明

> 本文档梳理当前程序化模型的**动作可行性**，以及后续落地的**具体实现计划**。  
> 与主文档 [`工业基建施工场景-项目生成说明.md`](./工业基建施工场景-项目生成说明.md) 配套：主文档管视觉与场景基线，本文档管动画扩展。  
> 穿模 / 碰撞 / 物理层见 [`场景穿模与物理碰撞方案说明.md`](./场景穿模与物理碰撞方案说明.md)（空间约束 SSOT；早期「不做物理」为阶段 3 取舍，后续以物理文档为准）。  
> 杆塔攀爬 + 多挂点作业见 [`杆塔高空作业实现说明.md`](./杆塔高空作业实现说明.md)（阶段 3.5）。  
> 人员网格、比例与近景约定见 [`人员模型优化方案说明.md`](./人员模型优化方案说明.md)（关节位置以该文为准）。  
> 挖掘机铲斗朝向、履带标记和液压缸外观见 [`挖掘机模型优化方案说明.md`](./挖掘机模型优化方案说明.md)（关节名与建造转角以该文为准）。  
> 技术栈：Vue 3 + TypeScript + Three.js + Vite  
> 风格约束：示意级施工可视化（Isometric + Stylized Low-poly），不做电影级写实角色动画。

## 1. 结论摘要

| 问题 | 结论 |
| ---- | ---- |
| 现有模型能否加动作？ | **可以**，但现状是「静态程序化模型 + 部分关节分组」，**尚无动画系统** |
| 人员跑/走/跳/爬 | **不能直接播**；示意级可用代码做，需先重构下肢关节；高质量动作建议换 GLTF 骨骼 |
| 车辆启停行进 | **最易落地**，对 `root` 做路径位姿即可；轮式可转轮 |
| 各车型机构动作 | **结构基本具备**（挖机臂、吊臂、滚筒、卷盘等），缺命名暴露与 tick 驱动 |

推荐推进顺序：

1. 车辆行进 + 启停  
2. 车辆机构动作（挖机 / 吊车 / 搅拌 / 卷盘）  
3. 人员示意级走 / 站 / 摆臂（先改腿部关节）  
4. 杆塔高空作业（示意攀爬 + 多挂点）→ [`杆塔高空作业实现说明.md`](./杆塔高空作业实现说明.md)  
5. （可选）人员完整动作或 GLTF 骨骼管线

## 2. 现状盘点（与动画相关）

### 2.1 建模与主循环


| 维度     | 现状                                                                 |
| ------ | ------------------------------------------------------------------ |
| 建模方式   | 全部为 `Box` / `Cylinder` 等拼装的 low-poly，**不是**带骨骼的 GLTF / FBX         |
| 人员     | 阶段 3 起为命名关节链（髋 / 脊柱 / 四肢）；网格与比例见 [`人员模型优化方案说明.md`](./人员模型优化方案说明.md) |
| 车辆     | 部分已有可转 `Group`（动臂、吊臂、搅拌筒、卷盘等），但多数**未 `name` 暴露**，也**无 update 驱动** |
| 主循环    | `SceneManager.startLoop` 仅更新相机与选中交互，**无实体动画 / Clock 驱动层**         |
| 动画依赖库  | 未接入骨骼 `AnimationMixer`；机构动画拟用自身插值或轻量 tween（按需）                      |


### 2.2 人员（`WorkerBuilder`）

本节是阶段 3 之前的盘点。当前工人已是髋 → 大腿 → 小腿 → 脚的关节链，关节名与网格比例见 [`人员模型优化方案说明.md`](./人员模型优化方案说明.md)。地面走跑见阶段 3，塔上作业见杆塔专文。

### 2.3 车辆建造器中的可动结构（已存在、待暴露）


| 车辆   | 关键可动节点（代码内局部变量）                         | 适合动作                         |
| ---- | ---------------------------------------- | ---------------------------- |
| 挖掘机  | `house`、`boomPivot`、`stickPivot`、`bucketPivot` | 回转、举臂、伸斗杆、铲斗开合               |
| 汽车吊  | `turret`、`boomPivot`、支腿、吊钩组              | 回转、变幅、伸缩臂（需再拆段）、收放钩、支腿展开    |
| 搅拌车  | `drumGroup`、`chutePivot` / `subPivot`    | 滚筒旋转、出料槽摆动                   |
| 卷盘车  | `spool`、牵引铰接点                            | 卷筒收放线、牵引缓行                   |
| 货运卡车 | `Wheel_*`、整车 `root`                      | 行驶、轮滚；装卸需再拆货箱                |


说明：上述节点在建造时已按机构拆分，动画成本主要是 **统一命名 + 注册到动画层 + 每帧驱动**。

### 2.4 与项目定位的关系

- 文档与视觉目标是「示意级工业基建可视化」，程序化机构动画与风格一致。  
- 不追求游戏级人物动作；若后续要高质量走跑跳爬，应另开骨骼模型管线，而非无限拧现有 Box 小人。

## 3. 能力矩阵与可行性

### 3.1 人员动作


| 能力              | 可行性    | 说明                                              |
| --------------- | ------ | ----------------------------------------------- |
| 整体平移（沿路径移动）     | 易      | 改 `root.position` + `rotation.y`                |
| 简易摆臂 / 点头       | 较易     | 复用 `armRoot`，正弦或关键帧                             |
| 像样的走 / 跑循环      | 需改造    | 腿改为「髋 → 大腿 → 小腿 → 脚」层级 + 周期关键帧                    |
| 跳、爬、蹲           | 中      | 依赖腿部关节 + 躯干俯仰；low-poly 下仅示意级                     |
| 接近游戏角色的动作质量     | 不推荐硬拧  | 换带骨骼 GLTF + `AnimationMixer`                    |


### 3.2 车辆通用：启停与行进


| 能力           | 可行性 | 说明                                      |
| ------------ | --- | --------------------------------------- |
| 启停 + 沿路径移动   | 易   | 对车辆 `root` 做位姿插值 / 路径跟随                  |
| 轮式车轮滚动       | 较易  | 卡车已有 `Wheel_*`，按行驶距离旋转                    |
| 履带「滚动」观感     | 中   | 履带为静态块；可贴图滚动或简化假动画，不做物理履带               |
| 启动视觉反馈（灯/状态） | 易   | emissive / 状态色，与位移解耦                      |


### 3.3 车型特定机构


| 车型  | 推荐首批动作              | 前置条件                        |
| --- | ------------------- | --------------------------- |
| 挖掘机 | 上车回转 + 动臂/斗杆/铲斗联动示意 | 命名 pivot，液压杆可先不动或后做长度联动     |
| 汽车吊 | 转台回转 + 吊臂变幅 + 吊钩上下  | 伸缩臂若要做，需将中臂/尖臂改为可沿轴向滑移的子节点 |
| 搅拌车 | 滚筒持续旋转 + 出料槽小幅摆动    | `drumGroup` 绕筒轴旋转           |
| 卷盘车 | 卷筒旋转 + 可选牵引缓移       | `spool` 绕轴旋转                |
| 卡车  | 沿路行驶 + 轮滚           | 路径点 + `Wheel_*`             |

## 4. 目标架构（实现层）

在不破坏现有 Builder 职责的前提下，增加「可驱动实体」层：

```text
src/scene/
  animation/                    # 新建
    AnimationClock.ts           # 统一 delta（或复用 Camera 侧 Clock 策略）
    AnimationRegistry.ts        # 按 objectId 注册可动画实体
    types.ts                    # Animatable、JointRef、Clip 描述
    controllers/
      VehicleMotionController.ts   # 启停、路径行进、轮滚
      ExcavatorActionController.ts
      CraneActionController.ts
      MixerActionController.ts
      SpoolActionController.ts
      WorkerLocomotionController.ts # 示意级走/站/摆臂（阶段 3）
    clips/                      # 可选：关键帧数据（角度序列）
  builders/
    WorkerBuilder.ts            # 阶段 3：下肢关节化 + 关节命名
    vehicles/*.ts               # 阶段 1–2：pivot / wheel 命名与暴露
  SceneManager.ts               # startLoop 内调用 registry.update(delta)
```

原则：

- **Builder 只负责建模并暴露关节引用**（`name` 或 `userData.joints`）。  
- **Controller 只负责每帧改旋转/位移**，不重建几何。  
- **业务层**（Store / API）只发「播放某动作 / 移动到某点」指令，不直接碰 Three 对象。  
- 保持示意级：默认循环短、幅度克制，避免干扰等距构图阅读。

### 4.1 关节暴露约定（建议）

建造结束时写入 `root.userData`：

```ts
interface AnimatableMeta {
  animatable: true
  objectId: string
  joints: Record<string, string> // 逻辑名 → Object3D.name，供 getObjectByName
}
```

人员建议关节名：`hips`、`spine`、`armL`、`armR`、`thighL`、`thighR`、`calfL`、`calfR`。  

车辆示例：

- 挖机：`slew`、`boom`、`stick`、`bucket`  
- 吊车：`turret`、`boom`、`hook`、`outriggerFL`…  
- 搅拌：`drum`、`chute`  
- 卷盘：`spool`  
- 卡车：`wheelFL`、`wheelFR`…

### 4.2 主循环改动要点

`SceneManager.startLoop` 增加：

1. `Clock.getDelta()`（或独立动画时钟）  
2. `animationRegistry.update(delta)`  
3. 再 `camera` / `interaction` / `render`  

卸载时 `registry.dispose()`，停止所有控制器，避免泄漏。

## 5. 分阶段实现计划

### 阶段 0：基础设施（0.5–1 天量级）

**目标**：可注册、可每帧更新、可启停。

- [x] 新增 `src/scene/animation/` 基础类型与 `AnimationRegistry`  
- [x] `SceneManager` 接入 `update(delta)`  
- [x] 约定并实现 `userData.joints` / `animatable` 元数据（`tagAnimatable`）  
- [x] 信息面板：全局「动态演示」开关 + 选中对象播放/停止  

**验收**：选中一台车后能启动/停止一段空转 demo（例如滚筒或转台微动），无内存泄漏。

---

### 阶段 1：车辆启停与行进（优先）

**目标**：卡车 / 工程车沿简单折线或样条移动，带启停。

- [x] `VehicleMotionController`：状态 `idle | accelerating | cruising | braking`  
- [x] 路径：世界坐标点列 + 朝向（yaw）  
- [x] 卡车：按位移累加驱动车轮旋转（`truck_01` / `truck_02`）  
- [x] 履带车整车路径行进（挖机 / 搅拌车 `CompositeAnimator` = 路径 + 机构）  
- [x] 与业务 Mock 预留：`runState = running | idle` 驱动播放（`applyMachineRunStates`）  

**验收**：至少 1 辆卡车、1 辆工程车完成「启动 → 行进 → 停车」，不穿模到关键设施（路径手写避让即可）。

---

### 阶段 2：车型机构动作

**目标**：各车有一段可读的循环或一次性示意动作。

#### 2.1 挖掘机

- [x] Builder：`joint_slew` / `joint_boom` / `joint_stick` / `joint_bucket` 命名并写入 joints  
- [x] 动作：回转 ↔ 挖斗联动（短循环）  
- [x] 液压缸长度联动：跨关节锚点 + `updateHydraulicFromAnchors`

#### 2.2 汽车吊

- [x] Builder：`joint_turret`、`joint_boom`、`joint_hook` 命名  
- [x] 动作：转台慢转 + 吊臂微幅变幅 + 吊钩上下（示意）  
- [x] 支腿落下（一次性，`joint_outrigger_*`）  
- [x] 伸缩臂：`joint_boom_mid` / `joint_boom_tip` 沿本地 Z 滑移

#### 2.3 搅拌车

- [x] `joint_drum` 绕筒轴持续旋转（运行态）  
- [x] `joint_chute` 小幅摆动  

#### 2.4 卷盘车

- [x] `joint_spool` 旋转模拟放线/收线  
- [x] 牵引头缓移（`joint_tractor`）+ 整车路径，与卷筒角速度粗同步  

**验收**：四类工程车各有一段可开关的机构 demo；性能仍满足普通办公机流畅。

---

### 阶段 3：人员示意级移动与姿态

**目标**：工人可沿短路径「走过去」，带摆臂与简易抬腿；**地面系统**不引入攀爬状态机。

- [x] 重构 `WorkerBuilder` 下肢为关节链（髋 / 大腿 / 小腿 / 脚）  
- [x] 上肢保持 `armL` / `armR` Group（挂 spine）  
- [x] `WorkerLocomotionController`：`idle` / `walk` / `run`（正弦相位抬腿 + 摆臂；跑更快、前倾）  
- [x] 根节点路径跟随 + 朝向（`worker_02` / `03` / `04`）  
- [x] 保留建造时 `pose` 作为 idle 变体（point / carry；walk 时锁定姿态臂）  

**明确不做（本阶段 · 地面人员）**：

- 真实攀爬、复杂跳跃状态机、手指级动画  
- 地面走跑与物理 CharacterController 强耦合以外的攀爬逻辑  

**验收**：至少 2 名工人完成 idle ↔ walk 切换与短路径移动。

## 6. 建议目录与接口草图

### 6.1 控制器接口（示意）

```ts
interface SceneAnimator {
  readonly id: string
  update(delta: number): void
  play(action: string, options?: { loop?: boolean }): void
  stop(): void
  dispose(): void
}
```

### 6.2 与现有模块衔接


| 模块                    | 职责变化                                      |
| --------------------- | ----------------------------------------- |
| `*Builder`            | 建模结束设置 joints / animatable                |
| `SceneManager`        | 持有 Registry，循环中 update，dispose 时清理        |
| `InteractionManager`  | 可选：选中后面板触发 play（不强制）                       |
| `siteStore` / API     | 后续：`status`、`task` 驱动动作，不直接操作 Object3D    |
| `ResourceDisposer`    | 动画层不新增 Geometry；仅停表与解绑即可                  |

## 7. 风险与约束


| 风险            | 应对                                      |
| ------------- | --------------------------------------- |
| 关节未命名导致难驱动    | 阶段 0 强制约定 joints 字典                     |
| 液压杆与臂角不同步     | 一期可不动液压外观；二期再 `createHydraulic` 动态重算    |
| 履带真滚动成本高      | 行进以整车位移为主，履带假动画后置                       |
| 人物关节重构影响摆位    | 保持脚底 y=0 与现有身高缩放逻辑                      |
| 动画过多影响性能      | 同时循环对象数量可控；远距可降采样 update 或停远处动画         |
| 破坏等距「插画」阅读感   | 默认动作慢、幅度小；提供全局「静态展陈 / 动态演示」开关（建议）       |
| 路径/机构穿模（无物理）  | 见 [`场景穿模与物理碰撞方案说明.md`](./场景穿模与物理碰撞方案说明.md)；主推 Rapier + 布局 SSOT |

### 10.1 优化后的运行约定

- `MAX_FRAME_DELTA_SECONDS` 是渲染、动画和物理的统一帧间隔上限，禁止各模块另设不同钳制值。
- `VehicleMotionController` 的路径积分只负责提交期望位姿；轮胎、链轮和履带板使用物理回写后的实际位移，车辆受阻时不得继续空转。
- 路径折点使用最短角阻尼转向；挖机从行进切换作业前必须经过 `braking` 并确认停止。
- 履带链轮和履带板在控制器构造期缓存，运行时禁止每帧遍历车辆子树。
- 卷盘车活动缆线由 `anchor_spool_*`、`anchor_tractor_*` 与 `dynamic_cable_*` 约束，更新时只改变线段变换，不重建几何体。
- `joint_*`、`hyd_*`、`anchor_*` 仍是 Builder 与 Controller 的稳定契约；模型优化不得直接改名。

### 10.2 模型细节层约定

- 新增结构优先强化中距离剪影和材质分层；驾驶室内饰、逐齿履带销和真实绳索动力学不进入程序化模型。挖掘机的铲斗朝向、履带标记和缸体半径见 [`挖掘机模型优化方案说明.md`](./挖掘机模型优化方案说明.md)。
- chrome、工作灯和软管必须通过 `MaterialFactory` 的语义方法获取，避免车型专用缓存键制造等价材质。
- 车轮与液压件允许共享 Geometry；共享后仍须保留 `Wheel_*`、`hyd_*` 子节点名称及独立变换。
- 装饰筋、螺栓、软管、螺旋绕线和动态缆线不投射阴影，主要车身与工作机构负责轮廓阴影。
- 搅拌筒细节必须挂在 `joint_drum` 下；汽车吊主绳由 `dynamic_crane_hoist_cable` 锚点更新。
- 卷盘绕线采用鼓身、少量分层环与螺旋线组合，不再通过高密度独立 Torus 堆叠细节。
